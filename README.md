# DermaTriage KZ

**Двухуровневый AI-триаж кожных новообразований для сельского и первичного звена здравоохранения Казахстана.**
Уровень 1 (этот репозиторий): по **фото с обычного смартфона** и **короткой анкете пациента** модель решает, нужно ли направить человека к специалисту.


> Это исследовательский прототип, не медицинское изделие. Не ставит диагноз; решение принимает медицинский работник.

---

## Задача в одном абзаце

Смертность от меланомы в Казахстане с 2019 по 2023 год выросла с 2,2 до 6,3 на миллион, а расходы на лекарства — почти в 10 раз (Adilova et al., 2026). Рак кожи излечим на ранней стадии, но в сёлах нет дерматологов и дерматоскопов. Поэтому система **отбирает подозрительные случаи** там, где есть только фельдшер и смартфон. Цель — **чувствительность ≥ 90%** к злокачественным образованиям (BCC, SCC, меланома) при минимальной доле лишних направлений.

**Тип AI-задачи:** computer vision + табличные данные; мультимодальная бинарная классификация (supervised learning) с переносом обучения и объяснимостью (Grad-CAM).

## Что внутри

| Часть | Где | Что делает |
| --- | --- | --- |
| Данные | `src/dermatriage/data/` | Загрузка PAD-UFES-20 и ISIC 2024, **разбиение строго по пациентам**, кодирование анкеты (fit только на train), аугментации «как со смартфона» |
| Модели | `src/dermatriage/models/networks.py` | Image-модель (EfficientNet-B0 / ResNet-50 / ViT-B/16 из `timm`) и мультимодальная «фото + анкета» (late fusion) |
| Обучение | `src/dermatriage/engine.py` | AdamW, косинусный LR с warmup, AMP, early stopping по AUC на валидации, кривые обучения |
| Метрики | `src/dermatriage/metrics.py` | AUC, pAUC при TPR ≥ 80% (метрика ISIC 2024), порог под чувствительность 90% **с валидации**, бутстреп 95% ДИ по пациентам |
| Объяснимость | `src/dermatriage/explain.py` | Grad-CAM для CNN и ViT (своя реализация) |
| Безопасность | `src/dermatriage/quality.py`, `inference.py` | Проверка качества снимка, «не уверен» по разбросу TTA, правило «красных флагов» |
| Демо | `app/app.py` | Веб-интерфейс Gradio для фельдшера: фото + анкета → решение + Grad-CAM |
| Эксперименты | `scripts/` | EDA, baseline, предобучение, обучение, анализ, сводка, `run_all.py` |
| Тесты | `tests/` | Отсутствие утечки, метрики, модели, Grad-CAM, сквозной прогон на синтетике |

## Установка

Нужен Python 3.11–3.13 (проверено на 3.13) и видеокарта NVIDIA (на CPU тоже работает, но обучение очень долгое).

```bash
git clone <ваш-репозиторий> dermatriage-kz && cd dermatriage-kz
python -m venv .venv
# Linux/macOS:
source .venv/bin/activate
# Windows (PowerShell):
.venv\Scripts\Activate.ps1

# 1) PyTorch под вашу CUDA — точную команду возьмите на https://pytorch.org/get-started/locally/
pip install torch==2.14.1 torchvision==0.29.1 --index-url https://download.pytorch.org/whl/cu130
# 2) остальное
pip install -r requirements.txt
# 3) проверка: GPU виден?
python -c "import torch; print(torch.cuda.is_available(), torch.cuda.get_device_name(0))"
# 4) автотесты на синтетических данных (~30 с)
pytest -q
```

Если `torch==2.14.1` недоступен для вашей CUDA, поставьте ближайшую версию с pytorch.org: код использует только стабильные API.

## Как запустить

**Сначала пробный прогон** (2 эпохи, 1 seed): проверяет, что весь план работает на ваших данных и железе.

```bash
python scripts/run_all.py --quick
```

**Затем полный план** (3 seed = 3 разных разбиения по пациентам; готовые шаги пропускаются, поэтому после сбоя можно просто перезапустить):

```bash
python scripts/run_all.py
```

Или по шагам:

```bash
python scripts/eda.py                                    # 1. EDA → reports/eda/
python scripts/calibrate_quality.py                      # 2. пороги качества снимка → configs/quality_limits.json
python scripts/baselines_tabular.py --seeds 0 1 2        # 3. baseline: константа, правило, LogReg, LightGBM
python scripts/pretrain_isic.py                          # 4. предобучение на ISIC 2024 (самый долгий шаг)
python scripts/train_pad.py --config configs/pad_effb0.yaml --seeds 0 1 2          # 5. модели
python scripts/train_pad.py --config configs/pad_mm_effb0_isic.yaml --seeds 0 1 2
python scripts/analyze.py --exp pad_mm_effb0_isic         # 6. разбор финальной модели → reports/analysis/
python scripts/collect_results.py                         # 7. сводная таблица → reports/results/results.md
```

Любой параметр конфига можно переопределить без правки файлов: `--set train.batch_size=16 train.epochs=30`.

**Частые проблемы:**

- Не хватает памяти GPU: `--set train.batch_size=16`.
- Ошибки DataLoader в Windows: `--set data.num_workers=0`.
- Нет интернета для весов ImageNet: `timm` скачивает их с Hugging Face при первом запуске, поэтому первый запуск нужно делать с интернетом.

## Демо

```bash
python app/app.py --model runs/pad_mm_effb0_isic/seed0
# откройте http://127.0.0.1:7860
# с телефона в той же Wi-Fi сети: --host 0.0.0.0, затем http://<IP-компьютера>:7860
```

Из командной строки:

```bash
python scripts/predict.py --model runs/pad_mm_effb0_isic/seed0 --image photo.jpg \
    --age 64 --gender MALE --region BACK --bleed yes --out cam.png
```

Логика решения: плохое качество → «переснимите»; риск ≥ порога → «направить»; есть красные флаги (кровоточит / менялось / растёт) → «направить по анамнезу»; модель нестабильна → «не уверена, нужен специалист»; иначе → «наблюдение, повторное фото через 1–3 месяца».

## Эксперименты

| Эксперимент | Конфиг | Зачем |
| --- | --- | --- |
| Константа | — | Нижняя граница (AUC = 0,5) |
| Правило «красных флагов» | — | Нечисловой клинический baseline |
| Анкета: LogReg, LightGBM | — | Сколько даёт одна анкета без фото |
| Фото: EfficientNet-B0 / ResNet-50 / ViT-B/16 (ImageNet) | `pad_effb0`, `pad_resnet50`, `pad_vit_b16` | Сравнение архитектур |
| Фото: EfficientNet-B0 (ISIC 2024) | `pad_effb0_isic` | Помогает ли предобучение на 400k «смартфонных» снимков |
| Фото + анкета (ImageNet / ISIC 2024) | `pad_mm_effb0`, `pad_mm_effb0_isic` | Вклад анкеты (ablation «фото / анкета / фото + анкета») |

Методика оценки:

- Три разных разбиения по пациентам (seed 0, 1, 2) → среднее ± стандартное отклонение.
- Порог выбирается на валидации под чувствительность ≥ 90% и **без изменений** применяется к тесту.
- 95% ДИ AUC — бутстреп по пациентам.
- Разбор по диагнозам и фототипам, эффект правила «красных флагов», галерея ошибок с Grad-CAM.

Результаты появятся в `reports/results/results.md` и `reports/analysis/` после обучения. Все числа в отчёте берутся только оттуда.

## Воспроизводимость

- Все параметры — в YAML-конфигах; итоговый конфиг каждого запуска сохраняется в `runs/<эксперимент>/seed<k>/config.yaml`.
- Сиды фиксируются (`seed`), для бит-в-бит повторяемости на той же GPU: `--set deterministic=true`.
- В `metrics.json` каждого запуска записаны версии пакетов, GPU и CUDA.
- Версии зависимостей зафиксированы в `requirements.txt`.

## Ответственный AI: риски и ограничения

- **Не диагноз.** Система только отбирает пациентов для осмотра специалистом; решение — за медработником.
- **Смещение по фототипу.** Данные из Бразилии (PAD-UFES-20) и клиник Европы, США и Австралии (ISIC 2024); тёмных фототипов мало. Качество по фототипам измеряется отдельно (`reports/analysis/.../fairness_fitzpatrick.png`); маленькие подгруппы → неустойчивые оценки.
- **Сдвиг домена.** Снимки ISIC 2024 — фрагменты 3D-фото из клиник, а не настоящие фото с телефона в ФАПе. До применения нужен пилот на локальных снимках.
- **Доля злокачественных в PAD-UFES-20 ≈ 47%**, в реальном потоке пациентов она гораздо ниже. Поэтому PPV (доля действительно больных среди направленных) в реальности будет ниже, чем на тесте.
- **Короткие пути в данных.** EDA проверяет, не предсказывается ли диагноз по факту пропусков в анкете; социально-бытовые поля (курение, водопровод и т.п.) в модель не включены.
- **Персональные данные.** Используются только открытые обезличенные наборы. Демо не ведёт базу снимков; загруженные фото хранятся во временной папке Gradio и удаляются каждые 10 минут. Сбор локальных данных потребует согласия пациентов и одобрения этического комитета.
- **Злоупотребление.** Демо не предназначено для самодиагностики: отказ от визита к врачу из-за «низкого риска» опасен, поэтому интерфейс всегда показывает дисклеймер и рекомендацию повторного осмотра.

## Отличия от Project Proposal

- Анализ справедливости сделан по фототипам, размеченным в самом PAD-UFES-20, а не на DDI / Fitzpatrick17k: у этих наборов другой тип снимков, и доступ к DDI выдаётся по заявке.
